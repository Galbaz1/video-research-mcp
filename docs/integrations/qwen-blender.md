# Owned local Qwen Blender session

The Blender adapter serves the original 22 Qwen tools from explicitly selected
external source and a separate compatible Python environment. It launches one
disposable factory GUI session with an owned profile, working directory,
temporary directory and loopback port. Ordinary installation and onboarding do
not activate it. The wrapper's tests verify admission, isolation, serialization and cleanup.
The selected Blender5.2.1LTS addon/discovery/scene/render/viewport journey passed
16 fixed local controls after one isolated-helper path correction; the original
pre-initialize failure is retained. The receipt is bound in the descriptor.
The own red cube/material/light/camera, saved scene and both rendered/viewport
images were read back and visually inspected. All four services stayed disabled;
no Requests attempts were recorded, and the owned process groups were absent
after closure. This qualifies the selected local primitive workflow. Live assets,
providers, complete host redistribution, human audit, comparison and release
remain separate gates.

The [descriptor](../../integrations/qwen/blender.json) selects 34 execution
sources and three complete grant/notice bodies from
[QwenLM/Qwen-MM-Plugins at the selected revision](https://github.com/QwenLM/Qwen-MM-Plugins/tree/07736672525443c7f8a3f6405eed37d2236f023f).
Source remains external and unmodified. MIT-derived addon/tools retain
© 2025 Siddharth Ahuja attribution and the full MIT grant; Qwen additions retain
the Apache-2.0 grant and Blender NOTICE. The owned startup changes registration
and session policy without copying the original native handlers. This route
does not redistribute Blender or qualify its complete third-party package
closure. The selected native Requests evidence remains a partial package
certificate; actual imports are an additional acceptance gate.

The external runtime must match the descriptor's selected Python and direct
package versions. It uses MCP1 and Pillow11 independently of the core MCP2 and
Pillow12 environment. No dependency installation, download, version resolution,
stock launcher, ambient Qwen configuration or core dependency change occurs.

Use the manually selected external Python with `-I`. Supply an independently
retained descriptor SHA256 and the selected executable SHA256. A fresh hash of
arbitrary current files is not a trusted selection receipt. A changed descriptor
requires its own reviewed receipt. All caller paths are explicit; session output
must be absent before starting:

```bash
/selected/external-runtime/bin/python -I -B /selected/product/scripts/blender_session.py \
  --source-root /selected/qwen-source \
  --manifest /selected/product/integrations/qwen/blender.json \
  --manifest-sha256 "$VRM_MANIFEST_SHA256" \
  --blender /Applications/Blender.app/Contents/MacOS/Blender \
  --blender-sha256 ea651e507c6b197df0e234bfa04e5ed43e7f4d498267a7df93fcb38f21928a5c \
  --output /selected/new-session \
  --check
```

`--check` hashes the selected source/grant/binary files and reads installed
package metadata. It reports readiness and an actionable interpreter hint,
without importing upstream modules, launching Blender, creating session output,
contacting a provider or installing anything. Remove only `--check` to run the
explicitly authorized local stdio session. In an installed wheel, the adjacent
adapter/startup are under `blender/scripts/` and the descriptor is under
`blender/integrations/qwen/`; the doc/skill retain their corresponding relative
tree under `blender/`. Select those actual paths
instead of the source-checkout paths shown above.

Blender launches interactively with `--offline-mode`, `--disable-autoexec` and
`--factory-startup`. The addon requires a GUI and a VIEW_3D area for screenshots;
background mode is incompatible. The startup imports the original addon under
an owned module name, suppresses its default listener during registration,
restores its original start method, disables autostart and all four integrations,
blanks credentials and starts the original server on the owned 127.0.0.1 port.
Requests `Session.send` raises immediately to deny provider and asset HTTP.
An owned `requests-denied.jsonl` exists before addon import; denied attempts
retain only method, scheme and hostname, omitting URL paths, query parameters,
credentials and bodies. An empty receipt supports the observed zero-attempt
claim for a controlled journey using this guard.
The child and serving environment use a credential whitelist; HOME and
CODEX_HOME remain unchanged. Empty owned config and cwd prevent Qwen settings
and MCP's `.env` settings from being inherited.

Readiness requires the exact live spawned PID, selected binary path, session
identity, owned port and disabled scene state, recorded by startup and read back
over the actual native listener. An existing open port or stale receipt cannot
establish readiness. Startup is bounded to 60 seconds. All original handlers
share one lock through native admission and complete return, including the
screenshot handler's temporary-file read and deletion. An owned TMPDIR prevents
ambient screenshot collisions. Native stdout/stderr go to `native.log`, outside
the MCP protocol stream. An owned transport observes stdin EOF and starts native cleanup before the
upstream framework joins cancellation-shielded tool workers. Stdio EOF, errors,
SIGINT and SIGTERM terminate the
owned native process group, wait up to five seconds, then kill and reap if needed.
The session directory preserves identity/config/log evidence after shutdown.

`execute_blender_code` runs arbitrary Python with ordinary host privileges. The
process/profile controls and transport denial are not a security sandbox; they
do not constrain code that deliberately bypasses them. Use only trusted,
host-authored code and a disposable synthetic scene. The socket protocol is
unauthenticated plaintext local TCP and has no framing, size or authorization
contract for remote service use. This adapter qualifies only an owned local
session on a shared filesystem, subject to actual runtime acceptance.

PolyHaven, Sketchfab, Hyper3D and Hunyuan tools remain advertised as original
tools, but their service routes are disabled. No external asset import is
authorized in this local route. Before any future external asset activation,
the operator must retain the selected source, license, attribution and import
receipt and separately authorize that operation, provider and spending scope.
Scene status, a generated job's DONE status or discovery of a schema does not
prove imported asset rights, completed scene geometry or useful pixels.

For research visualization, retain the trusted scene script, explicit source
claims, saved `.blend`, rendered images and actual viewport evidence. Inspect
exact object transforms, materials, mesh/AABB and image dimensions. Scene info
lists at most ten objects and rounds locations; use object-level or trusted
native readback for exhaustive validation. A successful build or mock test
cannot replace that scene and image inspection.
